# 2026-08-21-001 — Remote audio drops out for a couple seconds mid-reply, then resumes without repeating

## Symptom
During a live Phase 1 manual test call, the agent's spoken reply went silent for a couple of
seconds mid-sentence, then continued — but not from the point it went silent, as if the model
had kept speaking the whole time and playback just lost audio for a couple of seconds. Happened
twice in one ~2 minute call. Not correlated with the caller making noise or speaking — occurred
while the caller was just listening quietly.

## What was ruled out
- Not a barge-in/interrupt artifact — happened independent of caller noise (separate from the
  "sniff causes barge-in" issue also observed in the same session, which is a distinct problem
  addressed by lowering `turn_detection.eagerness` to `"low"` in `client/app.js`).
- Not a code-level audio manipulation bug — `client/app.js`'s `pc.ontrack` handler does nothing
  but `remoteAudioEl.srcObject = e.streams[0]`; there is no custom audio processing, buffering,
  or gain logic in this codebase that could introduce a client-side dropout on its own.
- Not an unhandled exception — nothing appeared in the browser console or backend log during the
  Phase 1 test call reporting this (per the caller's own account; needs re-confirming against
  actual console output next occurrence, now that the chrome-devtools MCP tab is wired up to
  watch it live).

## Current best hypothesis
A WebRTC media-path glitch (jitter buffer underrun / packet loss) between OpenAI's Realtime
servers and the local browser's audio decoder — plausible on a home network, and consistent with
the caller's own read that the model "was speaking the whole time" and only playback was
affected, not generation. Not yet confirmed with hard evidence (no `chrome://webrtc-internals`
packet-loss/jitter stats captured during an occurrence).

## Next steps if this recurs
- Capture `chrome://webrtc-internals` stats (packet loss, jitter, audio level) during the next
  occurrence, ideally with the chrome-devtools MCP tab already attached so console output is
  captured simultaneously.
- Try a wired connection instead of Wi-Fi to rule out local network jitter.
- If it recurs consistently (not intermittently) even on a stable connection, escalate — Phase 2+
  builds directly on this connection being reliable per `CLAUDE.md`.
