# 2026-08-21-003 — Truncated Claude JSON response crashed the graph invocation uncaught

## Symptom
During a live Phase 3 test call, the backend logged an unhandled `json.decoder.JSONDecodeError:
Unterminated string` traceback from inside `node_capture`, and that call's `/bridge` connection
closed abruptly (the caller got no reply for that turn). The rest of the backend process kept
running fine — only that one call was affected.

## Root cause
`call_claude_json` (`backend/supervisor/llm_utils.py`) parses the model's JSON response with
`json.loads(text)`. When the response text was truncated mid-string (likely a `max_tokens=256`
cutoff), this raised `json.JSONDecodeError` — but `call_claude_tool`'s retry/failure wrapper only
caught `anthropic.APIError`, not JSON parsing errors. The exception propagated straight out of
`node_capture`, past the `except LLMCallFailed` handling that exists specifically to catch this
class of failure gracefully (`CLAUDE.md` rule 7 / `cross-cutting.md` section 1) — because it
never became an `LLMCallFailed` in the first place.

## Fix
`call_claude_tool` now catches a `RETRYABLE_ERRORS` tuple —
`(anthropic.APIError, json.JSONDecodeError, StopIteration)` — instead of just `anthropic.APIError`.
A malformed/truncated response is retried exactly like an API error, and still raises
`LLMCallFailed` after the retry is exhausted, which `node_capture`/`node_routing` already handle
gracefully. Also bumped `max_tokens` from 256 to 512 in `call_claude_json`/`call_claude_text` as
defense-in-depth against truncation in the first place. Added `backend/tests/test_llm_utils.py`
(previously missing despite being specified in `cross-cutting.md` section 1) covering first-try
success, retry-then-success, and retry-exhausted paths.
