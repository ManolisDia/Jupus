# 2026-08-24-003 — `mark_call_abandoned` raced the per-call lock, could silently revert or lose a call's outcome

## Symptom
Found by a 6-agent codebase review (`docs/code-review-2026-08-24.md` finding #1), not from a live
symptom yet — a real, confirmed concurrency bug caught before it caused visible corruption.

## Root cause
`mark_call_abandoned` (`backend/dispatcher.py`) mutated `CALL_STATES[call_id]` and wrote the DB
outcome without holding `dispatcher.get_lock(call_id)` — the same lock `process_supervisor_call`
holds for the whole duration of a turn, including the (potentially multi-second) `GRAPH.invoke`
call. A caller disconnecting while a turn was mid-flight raced `mark_call_abandoned` against that
turn's own `CALL_STATES[call_id] = updated` / `repos.calls.upsert(updated)` calls, with no
ordering guarantee. Whichever write landed second silently won: a real booking finishing after
`mark_call_abandoned` had already run would get overwritten back to `outcome="abandoned"`, or a
disconnect landing after a turn had already started writing could get its own "abandoned" write
clobbered by the turn's normal completion.

## Fix
`mark_call_abandoned` is now `async` and acquires `get_lock(call_id)` before touching anything —
a disconnect landing mid-turn now correctly waits for that turn to fully resolve (including its
own `CALL_STATES` write and DB upsert) before deciding whether the call should actually be marked
abandoned, rather than racing in. `backend/app.py`'s `/bridge` handler now `await`s the call.

Regression test (`backend/tests/test_dispatcher_async.py::test_disconnect_waits_for_in_flight_turn_before_marking_abandoned`)
drives this with real thread coordination — a mocked `GRAPH.invoke` blocks on a `threading.Event`
(it runs on an `asyncio.to_thread` worker thread, so `asyncio.Event` isn't usable here) while a
concurrently-launched `mark_call_abandoned` call is asserted to be genuinely blocked behind the
lock, not racing in; once the turn resolves with a real `"ended"`/booked outcome, the abandon call
proceeds and correctly does *not* overwrite it.
