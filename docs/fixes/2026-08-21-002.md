# 2026-08-21-002 — Malformed email domain ("x@...com") passed validate_email

## Symptom
During a live Phase 3 test call, saying a deliberately garbled email produced `manoj@...com` in
the transcript. Extraction confidence landed at exactly 0.75 (the auto-confirm threshold), and
`validate_email` accepted the value as valid, so the call skipped the confirm-back loop entirely
and confirmed the field outright.

## Root cause
`EMAIL_PATTERN = r"^[^@\s]+@[^@\s]+\.[^@\s]+$"` — the domain half's character classes
(`[^@\s]+`) don't exclude `.`, so a domain like `...com` matches: the first `[^@\s]+` greedily
consumes `..`, the literal `\.` matches the third dot, and the final `[^@\s]+` matches `com`.
Leading, trailing, or repeated dots in the domain were never actually rejected.

## Fix
Tightened the domain half specifically: `^[^@\s]+@[^@\s.]+(\.[^@\s.]+)+$`. Each domain label
(`[^@\s.]+`) now explicitly excludes `.`, so a label boundary requires a real non-empty segment
on both sides of every dot. Local part stays permissive (`[^@\s]+`, dots allowed, matching
`j.smith@example.com`-style addresses). Still a documented simplification, not full RFC 5322 —
this only closes the specific malformed-domain gap, not every edge case.

## Why this wasn't caught by confidence tuning instead
The instinct was to make Claude's extraction confidence "stricter," but confidence scoring is
inherently fuzzy and Claude has no ground truth for what the caller actually said — that's
exactly why `CLAUDE.md`'s doctrine puts the deterministic validator in as an override on top of
confidence, not a replacement for it. (At the time this fix was written, that override lived in
`apply_extraction`; a later Phase 3 change moved email/phone format checking into `node_capture`'s
`_is_valid_format` instead, since email/phone are now always confirmed back regardless of
confidence — see `docs/DECISIONS.md`. The regex fix itself is unaffected by that later move.) The
regex being too loose was the actual bug; tightening it is the reliable fix, not chasing a
probabilistic score.
