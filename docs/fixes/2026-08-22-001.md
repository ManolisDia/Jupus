# 2026-08-22-001 — Caller's first real question got silently discarded by a content-blind greeting stub

## Symptom
Live Phase 5 testing: on nearly every call, the caller's first substantive utterance (e.g. "I
need to book a consultation... my boss is trying to fire me over my visa status") produced no
real answer — the agent just repeated the same generic "Thanks for calling — let me get you
sorted." line it would say for literally anything, and appeared stuck/unresponsive until the
caller spoke again.

## Root cause
`node_greeting` (`backend/supervisor/graph.py`) was a Phase 2 stub carried forward unchanged: it
never reads `state["transcript"]`, always replies with the same canned line, and always
transitions `stage` from `"greeting"` to `"routing"`. `build_graph()` wires every node with
`g.add_edge(name, END)` — a hard one-node-per-turn design — so whichever node runs first for a
call always returns control (and a spoken reply) to the caller immediately, with no continuation
within the same dispatch.

Since `CALL_STATES` starts every new `call_id` at `stage="greeting"`, the caller's *first*
`ask_supervisor` call — whatever it actually contains — always lands on this content-blind stub.
The real content is preserved in `state["transcript"]` for later, but nothing actually reads it
until a *second* `ask_supervisor` call reaches `node_routing`. Meanwhile the Realtime client's own
instructions already have it deliver a proper spoken greeting itself (rule 1, `client/app.js`),
without ever calling `ask_supervisor` for it — so `node_greeting`'s own canned reply was also
redundant, not just content-blind.

## Fix
1. `node_greeting` no longer produces its own spoken reply — it's now a silent stage-bump only
   (no `pending_reply`, no agent transcript turn), since the Realtime client already handles the
   actual verbal greeting.
2. `dispatcher.process_supervisor_call` (`backend/dispatcher.py`) now chains straight into a
   second `GRAPH.invoke()` when the turn started at `stage == "greeting"` and didn't immediately
   land on `"ended"`/`"escalation"` — so the caller's first real utterance gets genuinely
   classified by `node_routing` (or wherever it actually leads) within the same dispatch, and the
   reply the caller hears is the real one, not the greeting placeholder.
3. Guarded so it only fires once, from `greeting`, and not when `is_explicit_human_request`
   already forced the turn straight to `escalation` before the graph ever ran — that's a real
   escalation, not a stub to skip past.

Regression coverage: `backend/tests/test_dispatcher_async.py::test_greeting_start_chains_into_next_node_same_dispatch`
(and two negative-case tests confirming the chain doesn't fire when already past greeting, or when
explicit-request escalation preempts it), plus `backend/tests/test_graph_transitions.py`'s
transcript-accumulation test updated for `node_greeting` no longer adding its own turn.

Two existing integration tests (`backend/tests/test_bridge_endpoint.py`) started a fresh call
through the real (now Claude-backed-from-turn-one) graph without mocking `classify_practice_area`
— previously harmless since greeting never touched Claude, now a live-network dependency that also
broke one test's fixed `time.sleep(0.1)` timing assumption. Both now mock
`backend.supervisor.tools.classify_practice_area` like the rest of the suite.
