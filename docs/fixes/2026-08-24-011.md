# 2026-08-24-011 — every latency stat since Phase 6a silently read as zero

## Symptom
`GET /api/eval/summary`'s `latency` field, and the "Latency p50"/"Latency p95" stat cards in
the admin panel, always showed `0ms` — on every real call this project has ever logged, not just
sparsely-instrumented ones.

## Root cause
`eval/insights_agent.py`'s `processing_latency_percentiles` computed round-trip latency by
pairing each `reply_delivered` trace event with the closest preceding `user_message` event. But
`record_event(..., "user_message", ...)` was never actually called anywhere in `dispatcher.py`,
`graph.py`, or `app.py` — it only appeared in that function's own docstring and in a test that
manually fabricated the event. `processing_latency_percentiles` degraded silently to
`{"p50": 0.0, "p95": 0.0}` on no data, which is exactly what "no `user_message` events exist"
produces — so the bug never surfaced as an error, just a permanently-zero number nobody
questioned. Discovered while scoping Phase 11 (real per-turn latency + cost instrumentation),
not by anyone noticing the zero.

## Fix
Rather than reintroduce `user_message` (a boundary nothing else needed), Phase 11 replaces the
whole metric with a real four-stage breakdown keyed off boundary events that already fire (or
should have) at points the dispatcher genuinely controls: `speech_stopped` (was received by
`dispatcher.on_bridge_message` but never actually recorded via `record_event` — a second,
smaller instance of the same "never actually wired up" bug, fixed alongside this one) and a new
`ask_supervisor_received` event recorded synchronously before the supervisor task is spawned.
`processing_latency_percentiles` is replaced by `latency_breakdown_percentiles` +
`_stage_durations_for_call` in `eval/insights_agent.py`. See
`docs/phases/phase-11-latency-observability.md` for the full stage design.

## Verification
`eval/tests/test_insights_agent.py`'s latency-stage tests (fabricated trace events, deterministic
timestamps) plus `backend/tests/test_dispatcher_latency_events.py`'s regression test asserting
`speech_stopped` now actually produces a `trace_events` row. Live verification (real, non-zero
stage numbers from an actual call) tracked as a Phase 11 DoD item.
