# 2026-08-21-001 — Remote audio dropped out for a couple seconds mid-reply, then resumed

## Symptom
During a live Phase 1 manual test call, the agent's spoken reply went silent for a couple of
seconds mid-sentence, then continued — but not from the point it went silent, as if the model
had kept speaking the whole time and playback just lost audio for a couple of seconds. Happened
twice in one ~2 minute call. At the time it seemed unrelated to caller noise — reported as
occurring while the caller was just listening quietly.

## Fix
Logged initially as a known issue with a WebRTC-jitter hypothesis (see git history for the
original entry). Turned out to be the same root cause as a separately-reported "background noise
causes barge-in" symptom from the same session: `semantic_vad` was misdetecting ambient noise as
speech, which could interrupt/restart response generation in ways that read as audio dropping out
mid-reply rather than an obvious interruption. Fixed by the same change that resolved the
barge-in issue — adding `session.audio.input.noise_reduction: {type: "near_field"}` and lowering
`turn_detection.eagerness` to `"low"` in `client/app.js`'s `sendSessionUpdate`. Confirmed not
recurring across several further live test calls in the same session after the fix.

## Why the original "not noise-correlated" read was misleading
The caller's own account was that this instance happened while listening quietly, not while
making noise — which looked like it ruled out a noise-detection cause. In practice, ambient noise
(fans, room tone, mic self-noise) doesn't require the *caller* to consciously make noise, so it
was still consistent with the same root cause once `near_field` noise reduction resolved it too.
